Instrumentation 1 of 3 · Front end

Angular: Datadog RUM, speaking W3C

apps/web/src/main.ts
datadogRum.init({ applicationId: '', clientToken: '', site: 'datadoghq.com', service: 'shipping-express', env: 'uat', version: '1.0.0', sessionSampleRate: 100, sessionReplaySampleRate: 100, trackResources: true, trackUserInteractions: true, defaultPrivacyLevel: 'mask-user-input', allowedTracingUrls: [{ match: (url) => url.startsWith(`${origin}/api/`), propagatorTypes: ['tracecontext'], // W3C traceparent }], plugins: [angularPlugin({ router: true })], });
apps/web/src/app/app.config.ts
providers: [ provideRouter(routes), provideDatadogRouter(), // route → RUM view provideDatadogErrorHandler(), // Angular errors provideHttpClient(withFetch()), ]
  • Every /api/* call carries traceparent, which OTel backends understand out of the box
  • Views, actions, errors and Session Replay per user
  • No change to Angular HttpClient calls
Key outcome
The trace starts in the customer's browser
Instrumentation 2 of 3 · Java services

Spring Boot: OpenTelemetry Java agent, zero code

apps/deploy/install-app.sh → systemd unit
# Who am I, and where do I send telemetry? OTEL_SERVICE_NAME=adt-service-a OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 OTEL_RESOURCE_ATTRIBUTES=deployment.environment.name=uat, service.version=1.0.0 OTEL_TRACES_EXPORTER=otlp OTEL_METRICS_EXPORTER=otlp OTEL_LOGS_EXPORTER=otlp # logs carry trace_id # Name the downstream behind an IP OTEL_INSTRUMENTATION_COMMON_PEER_SERVICE_MAPPING= 10.0.1.176=service-b java -javaagent:opentelemetry-javaagent.jar -jar app.jar
